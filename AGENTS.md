# Codex Working Rules

1. Explain the plan before making changes.
2. Do only one small, clear task at a time.
3. Do not modify unrelated files.
4. Do not expand requirements without explicit approval.
5. Do not introduce complex dependencies without a clear project need.
6. Do not hardcode API keys.
7. Do not print secrets, passwords, tokens, or API keys.
8. Do not install unrelated dependencies.
9. After code changes, run a build or clearly explain why a build was not run.
10. After changes, output a change summary and `git diff --stat`.
11. Keep the app buildable after each implementation step.
12. Prefer small, reviewable changes over broad rewrites.
13. Record important project-level decisions in `DECISIONS.md`.
14. Record implementation-level or architecture notes in `docs/DECISIONS.md` when useful.
