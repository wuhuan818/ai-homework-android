# AI 协作说明

## 人类角色

人在项目中负责选题判断、产品方向、边界确认、真实 API 配置、真机手测和最终取舍。关键判断包括：优先完成安卓生成式内容创作工具闭环；保留演示模式但不把演示结果伪装成真实模型结果；发现并反馈 UI 拥挤、按钮换行、提示词显示不全、历史页和创作页卡顿、加密存储边界、裁剪交互等问题；决定暂缓账号系统、云同步、图生图、局部重绘、专业图片编辑器和多模型排行。

真实 API 配置、真机安装、生成结果可用性、UI 体验和最终取舍均由人进行确认，AI 不直接替代最终判断。

## AI 角色

GPT 主要用于任务拆分、方案讨论、Prompt 设计、风险提醒和文档草稿。Codex 主要用于代码实现、构建检查、日志整理、提交材料生成和 Git 操作。AI 的输出经过人工目标约束和人工验证，不等同于“全部由 AI 完成”。

## 关键迭代过程

项目从 Mock 演示链路开始，逐步接入真实 API；从文本创作扩展到图片描述、图片生成、历史、收藏、分享和保存相册；图片处理从旋转、水印扩展到黑白滤镜、中心裁剪、框选裁剪；图片生成从基础调用扩展到提示词优化和文本结果生成配图；本地安全从 API Key 与历史加密扩展到新生成图片文件加密；性能从功能可用优化到历史缩略图懒加载和创作页异步预览。

## AI 错误与人工纠偏

人工持续纠正项目表达，避免把 Android 应用写成泛泛的毕业设计说明；在 UI 阶段发现按钮换行、布局拥挤和提示词显示不完整；在性能阶段发现历史页与创作页切换卡顿；在安装和报告阶段要求不重复或伪造真机验证；在图片处理阶段明确中心裁剪不是最终目标，后续单独实现手势框选裁剪。

## 能力体现

批判思维体现在没有盲目堆功能，而是明确本地加密边界和不做账号、云同步、图生图、复杂编辑器。提问能力体现在多阶段拆分 14-1 到 14-7，每阶段有目标、边界和验证。整合能力体现在 Compose UI、模型 API、图片处理、FileProvider、MediaStore、Android Keystore、AES-GCM、历史缓存和性能优化的组合落地。学习能力体现在短时间内完成 Android 真机调试、API 配置、加密、图片处理和性能问题定位。
